# Player UI and Previous reader

UI-only branch: `podcast/player-ui-previous`. This change does not alter the Worker, auth, cookies, credentials, retention, workflows or deployment configuration. Integrate it with the separately reviewed backend/CI change before deployment. The UI consumes the existing authenticated `/api/episodes` response with `id`, `title`, `created`, `expires` and `chapters`; it filters expired items again, sorts newest first and displays at most 20 actual recordings. It does not invent recordings, publish audio or retain expired bytes.

The supplied reference image was viewed before design. The redesign follows its dark charcoal/indigo glow, centered light typography, quiet labels and rounded control surfaces. Existing Web Audio speech-reactive orb, reduced-motion rules, immediate pause and user-gesture play/resume remain. Today and Previous use keyboard-accessible tabs. No microphone, third-party fonts or analytics are used.

The reading room contains the two existing public news HTML reports listed by `podcast/reports.json`: the 18 October revised edition and early preview. Both source URLs returned HTTP 200 during preparation. `node scripts/build-reports.mjs` refreshes `src/reports.js` from that public manifest and the public HTML files; run it when a new public edition is added. This is a build snapshot, not an automatic runtime feed. Do not add private narration, private links or transcripts to that manifest or generated module.

Reports are not embedded as executable HTML or iframes. The builder extracts an allowlist of text blocks and HTTPS source links; the browser reconstructs headings/paragraphs through `createElement` and `textContent`, with HTTPS-only links and `noopener noreferrer`. No `innerHTML`, event attributes, scripts, images, forms or remote resources are imported. The in-app reader therefore needs no CSP relaxation. Public written history stays available independently of the seven-day audio window.

Validation: `npm test` passes 19 tests, including reader injection/URL guards, actual-manifest consistency, tab keyboard navigation, no-fabricated-recordings empty state, expiry filtering and the prior authentication/playback regressions. Wrangler build-only dry run passes. Actual browser screenshot QA covered the desktop Today view, 390×844 mobile Today/Previous/reader views, source links, and no horizontal overflow. The mobile reader contained 9,068 characters from the existing revised report and zero script/iframe/image nodes; browser error logs were empty. Screenshots were inspected in the browser tool; the local preview used only synthetic session responses and an empty recordings fixture. No production PIN or live media was used.
